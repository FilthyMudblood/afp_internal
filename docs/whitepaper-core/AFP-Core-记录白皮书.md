## 0. 一句话

合法的规划步和工具调用，也可以把一台机器堆死。AFP-Enterprise 是主机内核：规划器在工具真正执行之前做同步预检，问这一步能不能跑。测过的有界任务能做完；测过的死循环和突发会被深度闸或压力硬隔离拦住。和普通逐步闸相比，多出来的不是「更好的首次拦截」，而是**未改写的残留执行遥测**（retained execution telemetry / stale-state retention）——**还不是钉在智能体身份上的禁闭。** 延迟带和隔离–恢复机写在规格里，这轮 traces 没走到。

## 1. 这是什么，不是什么

### 1.1 是什么

AFP-Enterprise 是本地规划器旁边缺的那一层：**主机运行时内核**。预检是规划器怎么调用它。

规划框架（LangGraph 等）决定下一步做什么。MCP / HTTP / 本地查找决定工具怎么执行。两者都不回答：

> 这一步应不应该执行？如果拒绝，下一次还管不管？

AFP-Enterprise 的回答是：规划器先上报遥测，再阻塞在预检上，得到 **放行 / 延迟 / 隔离**。内核按顺序看：紧急停机、深度闸、四轴压力硬隔离、隔离–恢复机。

它不看自然语言，不解析 tool schema，不判断任务对不对。它看的是物理量：递归深度、并发、内存、上下文体积、即将扇出的任务数。

### 1.2 不是什么

| 不是 | 说明 |
|------|------|
| 对齐 / 注入防御 | 不替代 AgentDojo、AI Control、MCP 安全 |
| 任务正确性 | 不评判答案好不好 |
| 开放网格协议 | 不管陌生人、治理头、信誉 |
| 已验证的现场安全 | 本机受控实验，不是生产机群 |
| 身份级后果持久 | 规格里写过；**当前实现记住的是上次上报的深度** |
| 已测完的恢复路径 | 延迟带和隔离–恢复机写在规格里；这轮 traces 没走到 |

规划器和工具不用换；sidecar 只决定下一跳能不能跑。

## 2. 问题

企业助手今天常见的形态是：**一个 LLM 规划器 + MCP / 本地工具**。还没有真正的多规划器互调，也已经够出事故。

规划器把任务拆开：查资料、拉网页、再拆一层。每一步都可以是合法 tool call。轨迹仍可能在物理上不可持续——递归加深、上下文变厚、一次 `expand` 甩出几十个后续请求。

现成的对策不够当唯一刹车：

| 现成手段 | 弱点 |
|----------|------|
| 框架 `recursion_limit` / `max_retries` | 跟会话走，会话结束就忘 |
| Token 预算 | 往往事后记账 |
| 网关按请求限流 | 规划器内部风暴可以根本不出网 |
| 进程内护栏 | 和优化器同一地址空间，无法单独作证 |

失败几何是**堆叠**：`规划器 → 工具 → 再规划 → …`，有时成环。风险随深度、扇出、上下文增长，不必出现「坏消息」。

AFP-Enterprise 针对的是这种**物理失控**，不是语义作恶。

## 3. 机制（按当前实现写）

### 3.1 放置

```text
规划器 / 工具
      │  先写后探
      ▼
主机内核
  紧急停机 · 深度闸 · 四轴压力 · 隔离–恢复机
      │
      ▼
放行 / 延迟(δ) / 隔离
```

预检必须在**不可逆意图或 I/O 之前**完成。规划器在收到回执前不得继续。没有「仅建议」模式。

参考实现是进程外 **sidecar**（Unix 域套接字 + gRPC）。Python SDK 把 LangGraph 节点和工具包一层：`afp_governed_node` / `afp_governed`。

### 3.2 一个 sidecar 一套内核

每个 sidecar 一套内核。本地规划器的预检必须问同一个对象。

当前实现里，探测上的可选对端字段**被忽略**。状态挂在主机 sidecar 上，不是按规划器身份分账。

### 3.3 内核四段（命中即返回）

预检不读 prompt。内核按顺序：

1. **紧急停机** — 开着则一律隔离，不管压力多少  
2. **深度闸** — 上报深度 \(> \texttt{MaxRecursionDepth}\)（默认 \(10\)）立刻隔离  
3. **压力硬隔离** — \(e \ge e^{\star}\)（默认 \(0.95\)）则隔离，**不进入**第 4 段  
4. **隔离–恢复机** — 前三段都通过才走到  

这轮 traces 打到第 2 段（死循环）或第 3 段（突发）。紧急停机、延迟带、恢复机没有走到。

### 3.3.1 压力怎么算

压力是最大值，不是平均。任一轴饱和，\(e\) 就饱和。

\[
e \;=\; \max\!\bigl(e_{\mathrm{tool}},\, e_{\mathrm{mem}},\, e_{\mathrm{ctx}},\, e_{\mathrm{burst}}\bigr)
\]

| 轴 | 公式（现实现） | 默认 | 管什么 |
|----|----------------|------|--------|
| 工具 | \(e_{\mathrm{tool}}=\min(1,\, n_{\mathrm{active}}/C)\) | \(C=50\) | 正在跑的 tool call |
| 内存 | \(e_{\mathrm{mem}}=\min(1,\, \mathrm{mem}/r_{\mathrm{oom}})\) | \(r_{\mathrm{oom}}=0.90\) | 主机内存 / 接近 OOM |
| 上下文 | \(e_{\mathrm{ctx}}=\min(1,\, b/B)\) | \(B=512\,\mathrm{MiB}\) | 上报的规划字节 |
| 突发 | \(e_{\mathrm{burst}}=\min(1,\, \hat{n}/C)\) | \(C=50\) | 即将扇出 |

\(\hat{n}\) 是探测上的 `estimated_tasks`；若为 \(0\)，实现按 \(1\) 计。S4 的 \(\hat{n}=48\) 得到 \(48/50=0.96\)，所以第 3 段硬隔离、0 次 GET。

深度不进 \(e\)，单独闸：`reported_depth > 10 ⇒ ISOLATED`。S3 报到 \(11\) 走这里。

### 3.3.2 延迟公式（规格；这轮没走到）

\[
\delta(e) \;=\;
\begin{cases}
500\,\mathrm{ms} & e \le 0.75 \\
500 + 1500\cdot\dfrac{e-0.75}{1-0.75}\,\mathrm{ms} & e > 0.75
\end{cases}
\]

告警线 \(500\,\mathrm{ms}\)，\(e\to 1\) 时 \(2000\,\mathrm{ms}\)。观察期试探固定 \(1000\,\mathrm{ms}\)。

### 3.3.3 隔离–恢复机（规格；这轮没走到）

四态：放行 / 延迟 / 隔离 / 观察。先打地板规则：

```text
签名无效  ∨  恶意尖峰  ∨  恢复分 < 0.3  ⇒  隔离
```

本机恶意尖峰定义为 \(\hat{n} > 50\)。S4 是 \(48\)，不走这条，走压力硬隔离。

| 当前 | 条件 | 下一态 |
|------|------|--------|
| 放行 | \(e>0.75\) | 延迟 |
| 延迟 | \(e<0.40\) 才回放行（不是 \(<0.75\)） | 放行 / 继续延迟 |
| 隔离 | 进入后满 \(64\) epoch | 观察 |
| 观察 | \(e>0.40\) | 立刻再隔离（重盖时钟） |
| 观察 | 满 \(128\) epoch **且** 恢复分 \(\ge 0.8\) | 放行 |

隔离时钟只在**进入**时盖章。后续被拒的探测不得刷新，否则一直有流量就永远恢复不了。

本机恢复分在单一主机桶上**固定为 \(1.0\)**。下面 A–C 式在这轮 traces 是空转的。

### 3.3.4 恢复分公式（规格；这轮空转）

**A — 证据更新**（\(\alpha=0.95\)，\(\beta=0.05\)）：

\[
v_{\mathrm{new}}=\mathrm{clamp}(\alpha v_{\mathrm{old}}+\beta s-\gamma p-\delta e,\;0,\;1)
\]

实现里 \(\gamma=e^{p}-1\)，\(\delta=0.1\,e\)。\(s\) 是吞吐成功，\(p\) 是失稳惩罚。

**B — 空闲衰减**（\(\lambda=0.01\) / epoch）：\(v_{\mathrm{eff}}=v_{\mathrm{hist}}\cdot e^{-\lambda\Delta t}\)

**C — 对数恢复**（地板 \(0.3\)，\(\kappa=0.02\)）：\(v_{\mathrm{rec}}= \min(1,\; 0.3+\kappa\log(1+\Delta t))\)

\(v<0.3\) 强制隔离。回满额还要 \(v\ge 0.8\)。

**本机评测不验证 A–C 和驻留。** 不要把第 5 节读成恢复分或身份滞回结果。

### 3.4 规划器怎么接

每一步规划、每一次工具：

1. `ReportInternalState(recursion_depth, context_bytes)`  
2. `PreFlightCheck(estimated_tasks, trace_id)`  
3. 放行则执行；隔离则在图状态上标注并停图，不把进程扔进无治理重试风暴

### 3.5 规格写过、实现还没钉住的部分

规格曾写：裁决字母绑在**身份**上，跨请求有效，直到非对称恢复（隔离驻留 64 周期，试用 128，可行性 \(\ge 0.8\) 才回满额）。

**当前实测不是这样。**

深度隔离看的是熵监视器里**上次上报的深度**。新图若上报 `depth = 0`，隔离消失。逐步闸若在请求开始时把深度清零，S1–S4 上与现在这套打平；只有「拦住后不改写再探」会分开。

因此：

| 说法 | 现在成立吗 |
|------|------------|
| 执行前能拦死循环和突发 | 是（测过的那组） |
| 有界任务不误杀 | 是（测过的那组） |
| 后果钉在身份上直到恢复 | **否** |
| 多规划器共用一台闸门互不影响 | **否**（后者能盖掉前者的深度） |

把第三、四条写成已验证，是过声称。

## 5. 实验记录

全部在一台个人电脑上。规划器默认是**确定性剧本**（CI 可复现）。这样把 sidecar 准入和 LLM 随机路由分开；0.5B 只记在 5.6。工具是真的：本地键值查找 + 本机 HTTP GET。对照是同一张图，闸门开 / 关。

主证据层级：

1. **主证据：** 剧本规划器 + 真工具 + 闸门开关  
2. **对照证据：** 无闸 / 逐步闸（请求开始清深度） / 现在这套  
3. **补充证据：** 本机 Qwen2.5 0.5B 自己决定是否调工具  
4. **附录级：** 500 节点蒙特卡洛（熔断不变量，不当现场结果）

### 5.1 深度-only（无工具）

| 场景 | 关闸 | 开闸 |
|------|------|------|
| 良性 3 步 | 做成 | 做成 |
| 空转 | 堆到 40 | 第 11 步隔离 |

文件：`runtime_trace.csv`。

### 5.2 主表：剧本 + 真工具

| 任务 | 关闸 | 开闸 |
|------|------|------|
| S1 短：查法国首都 1 次 | 做成，1 工具 | 做成，1 工具，3 次预检，无误杀 |
| S2 长：4 次查找 + 4 次 GET | 做成，8 工具 | 做成，8 工具，17 次预检，无误杀 |
| S3 死循环 `tick` | 39 工具，深度 40 | 第 11 步隔离，10 工具 |
| S4 突发 `expand n=48` | 49 工具跑完 | 一开始拒，0 次 GET，熵 0.96 |

文件：`llm_tool_trace.csv`。墙钟为数十毫秒，不当压测。

**可写进结论的句子：**

> 在受控的 planner–tool 运行时中，当前测过的有界任务可以完成，测过的死循环和突发可以被闸门拦截。

不可写成：「AFP 已防止多智能体资源耗尽。」

### 5.3 三路对照（无闸 / 逐步闸 / 现在这套）

有界任务扩到五种：S1、S2、只查找、只拉取、同一 lookup 重复 8 次。

| 闸门 | 有界做成 | S3/S4 隔离 | 拦住后不改写再探 | 新任务报 0 |
|------|----------|------------|------------------|------------|
| 无闸 | 5/5 | 0/2 | — | — |
| 逐步闸 | 5/5 | 2/2 | 放行 | 做成 |
| 现在这套 | 5/5 | 2/2 | 拒绝 | 做成 |

有界任务误拒全为 0。本机受控跑次里，有界任务闸门大约多 2.2 ms（3.8 ms vs 6.0 ms）。这只是示意，不是吞吐或可扩展性压测。

| 场景 | 无闸 | 逐步闸 | 现在这套 |
|------|------|--------|----------|
| 5 类有界任务 | 完成 | 完成 | 完成 |
| 误拒 | 0 | 0 | 0 |
| 死循环 / 48 突发 | 不拦 | 拦 | 拦 |
| Stale probe，不改写旧状态 | — | 放行 | **拒绝** |
| 新任务报 0 | — | 放行 | 放行 |

**含义：** 审稿人问「为什么不是普通逐步策略」。S1–S4 **不区分**两种有闸变体。行为差别只出现在后续执行复用未清除的旧 telemetry 时。增量价值非常具体：stale-state containment。不要写成「AFP 提供 consequence persistence」。

文件：`baseline_trace.csv`。

### 5.4 跨请求（不要叫身份持久化）

同一 sidecar，先 S3 隔离，再：

| 臂 | 结果 |
|----|------|
| 不改写，直接预检 | 仍拒（深度 11） |
| 新 S1 自己上报从 0 起 | 放行并做成 |

证明的是：**闸门保留上次上报，直到被下一次上报盖掉。**  
不证明：后果绑在身份上，或 dwell / 恢复语义。

文件：`persist_trace.csv`。

### 5.5 两个本地规划器

| 布局 | A（S3） | B（S1） |
|------|---------|---------|
| 两个 sidecar | 隔离 | 做成 |
| 共用一个 sidecar | 隔离 | 做成（B 的上报盖掉 A 的深度） |

状态所有权在多规划器下是显式边界：隔离的是**主机监视器**，不是 DID。企业里要互不影响，需要一人一台闸门，或先改内核按身份分账。

文件：`two_agent_trace.csv`。

### 5.6 本机小模型（补充，不承担主论证）

Ollama，Qwen2.5 0.5B，同一套图和工具。

| 任务 | 关闸 | 开闸 |
|------|------|------|
| S1 | 做成 | 做成，无误杀 |
| S2 | 未做完（图递归上限） | 未做完；乱调工具后第 11 步被隔离 |

0.5B 走不完八步配方。开闸拦住的是模型自己的失控，不是「误杀已做完的长任务」。不能写成已验证的 LLM agent。

文件：`llm_tool_trace_live.csv`。本机推理，不消耗云厂商 token。剧本主表为 0 token。

### 5.7 500 节点仿真（附录）

死亡定义为负载 \(\ge 1\)，闸门拒绝任何使 `load+request > 0.95` 的增量。于是开闸生存率 100% 是**构造不变量**，不是现场结果。关闸同多种子塌缩。消融：只开熔断即可得到该不变量；只开可行性分数与无闸同类。

**禁止当标题结果。**

## 10. 明确不主张

- 生产级、in-the-wild、计算机使用或 MCP 入站评测  
- 身份持久惩罚、身份轮换对抗  
- 延迟带或隔离–恢复机已被这轮 traces 打到  
- 可行性分数、陌生人税、gossip  
- 500 节点 100% 生存是现场结果  
- Qwen 0.5B 已验证长任务 LLM planner  
- 共用一台 sidecar 时按身份隔离  
- AFP-Enterprise 替换限流、沙箱或人类监督  

这些结果能指出当前实现与逐步闸差在哪（残留深度），不是生产安全的验证。不要写 identity-persistent penalty、production safety、LLM-agent validation、scalability，或已普遍防止资源耗尽。
