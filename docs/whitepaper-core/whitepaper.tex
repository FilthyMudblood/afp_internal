\title{\textbf{AFP-Enterprise: Evaluating Host-Level Runtime Containment for Planner--Tool Execution}}
\author{Muchen He\\Independent Researcher}
\date{7 October 2026}

\begin{document}
\maketitle

\begin{abstract}
AFP-Enterprise is a host runtime kernel beside a local planner, reached by a synchronous pre-flight probe.
Before irreversible tool I/O, the planner reports recursion depth and context, then blocks on allow, delay, or isolate.
The kernel does not parse prompts or tool schemas.
It checks, in order, an emergency stop, a depth cap, a four-axis pressure maximum, and a specified isolate--recover state machine.

On a personal computer, a LangGraph planner issued real lookup and loopback HTTP GET calls.
Five bounded jobs completed under no gate, a per-step wipe, and the current sidecar (false isolate $=0$).
A scripted loop and a 48-task burst ran to completion without a gate and were contained by both gated variants.
Those traces fire the depth cap and the hard pressure isolate; they do not reach the delay band or the recover machine.
The gated variants differ only when a later probe reuses leftover host telemetry: AFP-Enterprise refuses; the wipe allows.
A new job that reports depth~$0$ is admitted under both.
Two planners on one sidecar can overwrite each other, so the kernel keeps last-reported host telemetry, not a lock on who the planner is.

The measured increment is retained execution telemetry, not identity-locked persistence, production safety, or LLM-agent validation.
A 500-node Monte Carlo in the appendix is a breaker invariant, not a field result.
\end{abstract}

\noindent\textbf{Keywords:} multi-agent systems; planner--tool runtime; admission control; pre-flight check; retained telemetry; stale-state retention; circuit breaker.

\section{The empty cell}

Multi-agent infrastructure has matured along two axes: planning (LangGraph, CrewAI, AutoGen) and transport (gRPC, HTTP, Kafka, MCP).
A third cell is empty.
Before each hop commits, something must answer: may this step execute?

MCP and A2A decide \emph{what} may be said.
They do not decide whether the next hop may run.
Per-request gateways forget.
Token budgets often account after commit.
Framework retry and recursion limits reset when the session ends.
In-process guardrails share the optimizer's address space.

The failure geometry is stacking: planner $\to$ tool $\to$ planner $\to\cdots$, sometimes closing a loop.
Each hop can be a valid tool call while depth, context, concurrency, and burst grow until the node saturates.

Three default pathologies:
\begin{itemize}
  \item \textbf{Intent burst.} One objective fans into tool chains. Wire metrics can stay quiet.
  \item \textbf{Recursive delegation loop.} Replan / reflect / retry stays syntactically valid while depth climbs.
  \item \textbf{Context avalanche.} Bounded depth does not bound state volume.
\end{itemize}

AFP-Enterprise adjudicates the physical question---will this step blow through depth, pressure, or burst?---not hallucination and not task correctness.
The scene is a local planner plus MCP or local tools on hosts the operator already controls.

\section{What AFP-Enterprise is}

Legal planner steps can still stack a machine.
AFP-Enterprise is a host kernel that answers, before the tool runs, whether this step may proceed.
Pre-flight is how the planner calls that kernel.

The planner does not embed the kernel.
Each hop is write-then-probe:
\begin{enumerate}
  \item report recursion depth and context bytes;
  \item probe with a burst hint (estimated imminent fan-out);
  \item proceed only on allow; sleep on delay; halt I/O on isolate.
\end{enumerate}

The probe must finish before irreversible I/O.
There is no advisory-only mode.
The reference placement is an out-of-process sidecar (Unix-domain socket and gRPC).

It is not alignment or injection defense, not a grader of answers, not a network ingress filter, and not validated field safety.
The delay band and isolate--recover machine are specified; these traces do not reach them.
The shipped sidecar keeps last-reported depth, not a lock on agent identity.

\section{Mechanism}

\subsection{Timing}

An action is pre-intent if and only if it is evaluated before the planner commits a tool call, delegation, or outbound message, or before irreversible I/O.
Parsing RPC after the fact is observation, not this kernel.
The contested resource is optimization capacity, not prompt text.

Each hop:
\begin{enumerate}
  \item \texttt{ReportInternalState(recursion\_depth, context\_bytes)}
  \item \texttt{PreFlightCheck(estimated\_tasks, trace\_id)}
  \item allow $\to$ execute; isolate $\to$ stop. Do not convert isolate into an ungoverned retry storm.
\end{enumerate}

If the state report is omitted or stale, pressure at probe time is under-measured.
An optional destination field on the probe is ignored.
State is kept on the host sidecar, not keyed to one agent identity.

\subsection{Four stages}

The kernel returns on the first match.
\begin{enumerate}
  \item \emph{Emergency stop.} An operator kill switch isolates every hop.
  \item \emph{Depth cap.} Reported depth $>$ \texttt{MaxRecursionDepth} (default $10$) isolates immediately.
  \item \emph{Pressure isolate.} If $e \ge e^{\star}$ (default $0.95$), isolate before the recover machine.
  \item \emph{Isolate--recover machine.} Only if the first three stages pass.
\end{enumerate}

These traces fire stage~2 (the loop) or stage~3 (the burst).

\subsection{System pressure}

Pressure $e\in[0,1]$ is a maximum, not an average.
If any axis saturates, pressure saturates.
\begin{equation}
  e \;=\; \max\!\bigl(e_{\mathrm{tool}},\, e_{\mathrm{mem}},\, e_{\mathrm{ctx}},\, e_{\mathrm{burst}}\bigr).
\end{equation}

\begin{center}
\small
\begin{tabular}{@{}llll@{}}
\toprule
Axis & Formula & Default & Captures \\
\midrule
Tool & $e_{\mathrm{tool}}=\min(1,\, n_{\mathrm{active}}/C)$ & $C=50$ & in-flight tool calls \\
Memory & $e_{\mathrm{mem}}=\min(1,\, \mathrm{mem}/r_{\mathrm{oom}})$ & $r_{\mathrm{oom}}=0.90$ & host memory / OOM \\
Context & $e_{\mathrm{ctx}}=\min(1,\, b/B)$ & $B=512\,\mathrm{MiB}$ & reported planning bytes \\
Burst & $e_{\mathrm{burst}}=\min(1,\, \hat n/C)$ & $C=50$ & prospective fan-out \\
\bottomrule
\end{tabular}
\end{center}

$n_{\mathrm{active}}$ is the live tool-call counter.
$\mathrm{mem}$ is the host memory-usage ratio.
$b$ is last-reported context bytes.
$\hat n$ is \texttt{estimated\_tasks}; if the hint is $0$, the monitor substitutes $1$.
The storm job $\hat n=48$ gives $e_{\mathrm{burst}}=0.96$, so S4 isolates on stage~3 with zero GETs.

\begin{center}
\small
\begin{tabular}{@{}lll@{}}
\toprule
Band & Value & Effect \\
\midrule
Safe $e_{\mathrm{safe}}$ & $0.40$ & machine may return to allow \\
Warn $e_{\mathrm{warn}}$ & $0.75$ & delay path (stage 4) \\
Breaker $e^{\star}$ & $0.95$ & hard isolate (stage 3) \\
\bottomrule
\end{tabular}
\end{center}

Depth is a discrete breaker, not folded into $e$:
\[
\texttt{reported\_depth} > 10 \;\Rightarrow\; \mathrm{ISOLATED}.
\]
S3 reports depth $11$ and isolates here.

\subsection{Delay injection (specified; not reached)}

If stage~4 chooses delay,
\begin{equation}
\delta(e) \;=\;
\begin{cases}
500\,\mathrm{ms} & e \le e_{\mathrm{warn}},\\[4pt]
500 + 1500\cdot\dfrac{e-e_{\mathrm{warn}}}{1-e_{\mathrm{warn}}}\,\mathrm{ms} & e > e_{\mathrm{warn}}.
\end{cases}
\end{equation}
Delay is $500\,\mathrm{ms}$ at the warn line and $2000\,\mathrm{ms}$ as $e\to 1$.
A probation probe uses a fixed $1000\,\mathrm{ms}$ window.

\subsection{Isolate--recover machine (specified; not reached)}

Four states: allow, delay, isolate, probation.
Floor rules fire first:
\[
\text{invalid sign}\ \lor\ \text{malicious spike}\ \lor\ v<0.3 \;\Rightarrow\; \mathrm{isolate}.
\]
A malicious spike is $\hat n>C$.
S4 uses $\hat n=48<50$, so the spike rule does not fire; the pressure breaker does.

\begin{center}
\small
\begin{tabular}{@{}llll@{}}
\toprule
Current & Condition & Next & Action \\
\midrule
Allow & $e>0.75$ & Delay & sleep $\delta(e)$ \\
Allow & otherwise & Allow & proceed \\
Delay & $e<0.40$ & Allow & proceed \\
Delay & otherwise & Delay & sleep $\delta(e)$ \\
Isolate & epochs since entry $\ge 64$ & Probation & $1000\,\mathrm{ms}$ probe \\
Isolate & otherwise & Isolate & halt \\
Probation & $e>0.40$ & Isolate & halt; clock restamps \\
Probation & dwell $>128$ and $v\ge 0.8$ & Allow & proceed \\
Probation & otherwise & Probation & low-rate probe \\
\bottomrule
\end{tabular}
\end{center}

Leaving delay requires $e<0.40$, not merely $e<0.75$.
The isolate clock stamps on entry; later dropped probes must not refresh it.
On the current local sidecar the recover score is held at $1.0$ for the single host bucket.
Formula~A is idle on these traces.

\subsection{Recover-score formulas (specified; idle)}

\textbf{A --- evolution} ($\alpha=0.95$, $\beta=0.05$):
\begin{equation}
v_{\mathrm{new}} \;=\; \mathrm{clamp}\!\bigl(\alpha v_{\mathrm{old}}+\beta s-\gamma p-\delta e,\;0,\;1\bigr),
\end{equation}
with shipped coefficients $\gamma=e^{p}-1$ and $\delta=0.1\,e$.
$s$ is throughput success; $p$ is a destabilization penalty.

\textbf{B --- idle decay} ($\lambda=0.01$ per epoch):
\begin{equation}
v_{\mathrm{eff}} \;=\; v_{\mathrm{hist}}\cdot e^{-\lambda\Delta t}.
\end{equation}

\textbf{C --- logarithmic recovery} (floor $0.3$, $\kappa=0.02$):
\begin{equation}
v_{\mathrm{rec}}(\Delta t) \;=\; \min\!\bigl(1,\; 0.3+\kappa\log(1+\Delta t_{\mathrm{probation}})\bigr).
\end{equation}

$v<0.3$ isolates.
Full return also requires $v\ge 0.8$ after $128$ probation epochs.
These traces do not validate A--C or the dwells.

\section{Shipped retention}

Older drafts stored isolate on identity until asymmetric recovery.
The shipped sidecar is not that.

Depth isolation follows last-reported recursion depth.
A new graph that reports depth~$0$ is admitted after isolate.
A per-step wipe that clears depth at request start matches the current sidecar on the bounded and first-containment jobs.
They differ only on a stale post-isolate probe that does not rewrite depth.

\begin{center}
\small
\begin{tabular}{@{}lc@{}}
\toprule
Claim & Holds now? \\
\midrule
Pre-flight stops the tested loop and burst & Yes, on those jobs \\
Tested bounded jobs are not false-isolated & Yes, on those jobs \\
Consequences stay on identity until recovery dwell & No \\
Two planners on one sidecar do not overwrite each other & No \\
\bottomrule
\end{tabular}
\end{center}

The accurate object is stale-state retention.

\section{Empirical record}

All runs used one personal computer, one LangGraph, and two real tools: a local key lookup and HTTP GET against a loopback fixture.
The primary planner is deterministic so sidecar admission is isolated from stochastic LLM routing; the live 0.5B arm is Appendix~\ref{app:live}.
Sidecar policy: recursion cap $10$, concurrency cap $50$.
No unfinished row is dropped.
Latency is indicative only.

Table~\ref{tab:primary} is no-gate versus current sidecar.
S1 and S2 finish with the gate on (false isolate $=0$).

Isolation is a host-level check.
If two planners must not affect each other, they need separate sidecars, or the kernel must account per identity first.

\section{Related work}

Admission control and circuit breaking are standard operations practice~\cite{jacobson1988,welsh2001,nygard2018,fowler2014,envoy2024}.
AFP-Enterprise does not invent that primitive.
It attaches a host kernel---depth cap, four-axis pressure, retained telemetry, and a specified recover path---before a planner--tool hop, and says which stages the traces reach.

Agent frameworks optimize task completion~\cite{yao2023,wu2023,langchain2025}.
Safety evaluations grade harmfulness, injection, and tool abuse~\cite{greshake2023,debenedetti2024,andriushchenko2024}.
Control and oversight constrain intent~\cite{greenblatt2024}.
MCP and A2A secure tools and sessions~\cite{anthropic2024,google2025}.
A valid tool call can still be a physically illegal next hop.

\section{Limitations}

The evidence is a controlled planner--tool environment on one machine.
It is not computer-use, MCP ingress, injection robustness, multi-agent isolation, or production safety.
The primary planner is scripted; the live 0.5B arm does not finish the long recipe.
Jobs are deterministic, so the tables have no confidence intervals.
The emergency stop, delay band, and isolate--recover machine were not reached.
State ownership fails on a shared sidecar.
These traces stop a false persistence claim.
They are not a complete runtime-safety benchmark.

\section{Conclusion}

AFP-Enterprise is a host runtime kernel for a local planner, reached by a pre-flight probe.
On the jobs that were tested, bounded work can finish, and a loop or burst can be stopped by the depth cap or the hard pressure isolate.
A per-step wipe can do the same on those jobs.
What the current sidecar adds is refusal when leftover host telemetry is not overwritten.
The delay band and the isolate--recover machine are specified; they are not evidenced by these tables.

\section{Synthetic mesh: an invariant, not a field result}
\label{app:mesh}

Death is load $\ge 1$.
The simulated gate refuses any request with $\mathrm{load}+\mathrm{request}>0.95$.
Under that pair of rules a node cannot die: $100\%$ survival is an invariant of the construction.
Without pre-accumulation refusal, the same seeds collapse (mean $1.876/500$ alive at $T=100$ over $1{,}000$ runs).
The $100\%$ cells are not a field result.
